How it works

A network that predicts, a planner that chooses.

The puck moves on a small table with walls and one bumper. A neural network learns how the puck moves from one step to the next. A planner uses that network to pick a push. Then the real simulator runs that push, and you compare.

The challenge

A planner gets one push to land a puck in a green ring after 35 steps. It picks the push by asking a small neural network to predict how the puck moves. The predicted path ends at or very near the target, but when the real simulator runs the same push, the puck often misses. Work out where the prediction goes wrong, change how the network is trained, and show with evidence whether the change helped.

One shot, step by step

  1. StatePosition and velocity: x, y, vx, vy
  2. Neural networkPredicts the change to the next state
  3. Repeat 35 timesEach prediction feeds the next one, giving a predicted path
  4. PlannerTries many candidate pushes and keeps the one whose predicted path ends closest to the target
  5. SimulatorRuns only the chosen push with the real physics

The planner never asks the simulator which push is best. It trusts the network. That is why a network that is wrong in a small way can still produce a confident plan that misses.

What the network is

A small multilayer perceptron with a 4 → 48 → 48 → 4 shape. Its input is the current state. Its output is the change in position and velocity for one step. Its training data comes from ordinary simulated puck trajectories, and the answers it learns from are the simulator's own next states.

Route 1: the known-geometry model

The improved network expresses bumper collisions in normal and tangent coordinates, so a collision at any angle shares one learned response. Free motion and walls use learned affine layers. The bumper uses a small residual 3 → 32 → 32 → 4 network. Known geometry decides which branch runs and supplies the coordinate transforms.

Every response is learned from observations. No reflection formula, restitution coefficient or collision projection overrides the network's output, and neither neural planner queries the simulator to rank actions. The optional calibrated physics reference is a separate, non-neural comparison and is not the workshop solution.

Route 2: the new approach, geometry inferred from the data

  1. Learn the gliding lawFrom the training data: the puck moves by its velocity and slows by a drag factor (about 0.985 per step).
  2. Find the collisionsAny step the gliding law cannot explain is a collision. About 3% of the original steps.
  3. Work out the tableWall hits give the wall positions. Positions just after bumper hits lie on a circle; fit it to get the bumper's centre and radius.
  4. Send each step to the right pieceGliding, wall or bumper, using the found numbers, not hand-written ones.
  5. Learn each piece from data, then score onceStraight-line fits for gliding and walls, a small network for the bumper in surface coordinates.

Result on the 96 scenes: 96 of 96 with the larger dataset and 94 of 96 with only the original data. A plain network with no geometry help scored 2 to 6 of 96 on the same data.

Still assumed: straight reflecting walls, one round bumper, a drag law, and noiseless data. Several things differ from the original network at once, so this does not show which one mattered most.

Run and score both

From the full puck-lab folder. Each scoring command takes about 20 seconds and prints the hits out of 96.

Known-geometry model:

python host/score_submission.py host/local_neural_repair.py

New approach (larger dataset), about 35 seconds to train:

python host/geometry_from_data_pipeline.py scratch/geofree expanded
python host/score_submission.py scratch/geofree/repair_local_inferred.py

New approach, strict (original 30,000 transitions only):

python host/geometry_from_data_pipeline.py scratch/geofree-orig original
python host/score_submission.py scratch/geofree-orig/repair_local_inferred.py

Score once, do not tune afterwards, and call the 96-scene set a public benchmark: it has been scored and shown before.

Why a plan can miss

Rare events

Collisions are a small share of the training data, so the network sees few examples of them.

Errors add up

Each step starts from the last prediction, so a tiny error can grow over 35 steps.

Optimistic picks

Searching many pushes favours the ones the network is most wrong about in its own favour.

One missed shot does not show which cause matters most. Testing it is the workshop. More candidate pushes can make the predicted miss look better without making the real result better.

Read the results carefully

The opening scene in the Lab is an illustrative layout explored during development, not an unbiased benchmark. Predictions and motion are computed live in your browser. Judge a change across many scenes, not one shot.
